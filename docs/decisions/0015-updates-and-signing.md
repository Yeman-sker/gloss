# 0015 自动更新读私有 Release，改用固定的证书签名

**日期：** 2026-11-07 **状态：** 已接受（GLO-37）

**背景：** 0.1.0 时负责人取消了自动更新（GLO-37），因为 Gloss 打算闭源，不想为了更新源公开任何东西。每次发版都要手动下载、去掉隔离属性、重新授权，负责人 2026-11-07 决定在 0.1.3 做上。

**决定：**

- **更新源：** 仍然是私有仓库 `Yeman-sker/gloss` 的 GitHub Release。mygo 的 `Updater.SetSource` 允许换来源，`app/update.go` 的 `ghSource` 用本机 `gh auth token` 的登录走 GitHub API 读最新 Release 和下载文件。GitHub 把文件跳转到另一个域名的存储，Go 跳转时不带 `Authorization`，token 只发给 `api.github.com`（有测试）。
- **校验：** 更新包由 mygo 的 ed25519 私钥签名，公钥写进 `mygo.json` 并编进程序。签名不对就不安装，和来源无关。
- **签名身份：** `make app` 用钥匙串里的 Apple Development 证书签名，不再 ad-hoc。designated requirement 变成“`dev.gloss.app` + Apple 签发 + 证书名”，每个构建都一样，辅助功能授权应该能跨版本保留。仍然不公证。
- **安装：** 后台下载、校验、暂存，用户点“重启以更新”时替换并重开；不点的话，Gloss 下次退出时替换（mygo 的行为）。
- **不做增量包**（`deltas: 0`）：mygo 要不登录读上一版的清单才能做，私有仓库读不到。

**实测（Apple M4，macOS 27，2026-11-07）：**

- 主程序 16,721,810 → 16,941,922 字节，多 220 KB（同样的发布参数编译 main 和这个分支）。
- 用 `open` 启动 0.1.3 正式包（证书签名、hardened runtime）：正常 `ready`；30 秒后用 gh 的登录读到真实私有仓库的最新 Release v0.1.2，按预期报告里面没有更新包。
- 端到端（仓库副本里只把 API 地址换成本地假服务器、token 换成假的）：0.1.3 检查到 0.1.4，下载 10.9 MB、校验、暂存用了 143 ms，重启后同一位置的 Gloss 是 0.1.4，签名校验通过，没有残留目录。把更新包改掉一个字节后，日志写 `the update is not signed with the app's key`，没有安装。
- 未测：从真实 GitHub 完成一次更新（要等 0.1.3 之后的版本）；更新后辅助功能授权是否保留；更新期间的内存。

**理由：** 不公开任何东西，也不在程序里放 token；和现在 `gh release download` 的访问权限完全一致。体积只多 0.2 MB。

**代价：**

- 只有装了 gh、登录了能看到仓库的账号的 Mac 才能自动更新。给别人用时要换来源（公开仓库、R2 或自己的服务器），`ghSource` 可以换掉，签名校验不变。
- 更新私钥只在负责人机器上，必须另外备份。丢了它，已安装的 Gloss 就收不到更新，只能手动重装新公钥的版本。
- 只有有这张证书的机器能打正式包；其他人 `make app SIGN=-` 打的 ad-hoc 包每次都要重新授权。证书过期续签后，证书名不变的话授权应该还在（推断，未测）。
- 从 0.1.2 换到 0.1.3 时，签名身份变了，要重新授权一次辅助功能。
