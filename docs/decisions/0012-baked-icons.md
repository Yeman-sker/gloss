# 0012 动态图标用烘焙帧，不在运行时跑引擎

**日期：** 2026-11-06 **状态：** 已接受（GLO-42）

**背景：** Kubai 图标的动效由 JS 引擎驱动，靠 SVG 滤镜出光影。mygo 不能跑 JS（守住“不引入 WebView”），也不画 SVG 滤镜。

**决定：** 构建时用 Chrome 跑引擎（`design/icons/scripts/bake.mjs`），把每个图标的悬停动效按进度均匀取样成 24 帧无滤镜 SVG，每帧一行，gzip 后放进 `app/icons/*.svgz`，再 `go:embed`。运行时用 `AnimateWith` 按引擎原有的曲线（460 ms，`cubic-bezier(.22,1,.36,1)`）走进度，取对应的帧。帧懒解析，动完只留首末两帧，关窗时全部释放。

**颜色：** 引擎按亮色页面配色，放到墨底上刺眼。烘焙时按角色重新定明度和彩度（OKLCH，色相不变）：填充压暗，内容保持最亮，描边居中；mask 里的黑白不动。进度带着亮度一起走，悬停时图标“醒来”亮一档。规则在 `bake.mjs` 的 `onInk`。

**实测（Apple M4，macOS 27，160Hz，2026-11-06）：** 11 个图标 × 24 帧，原始 603 KB，gzip 21.7 KB。真实窗口里切 24 次页（每次约 70 帧，含页面淡入和图标形变）：帧间隔 p50 6.2–6.3 ms，p95 最高 9.1 ms，最长一帧 21.6 ms。数据和内存对比见 [0.1.1 设置界面实测](../research/2026-11-06-settings-ink.md)。

**理由：** 不增加运行时依赖，不跑脚本，体积几乎可以忽略。

**代价：** 改图标要重新烘焙，需要 Node 和 Chrome（只有开发时）。滤镜的投影和内发光丢失，暗底上差别很小。动效只能按进度正放和倒放，不能做依赖时间的循环。13pt 的按钮看不清这种图标，所以小操作用单色字形（`app/glyphs.go`）。
