## 当前重点

**只做 macOS。** Windows 开发自 2026-11-05 起暂停（负责人决定），Linux 也不考虑。代码继续保持跨平台写法，但不再为 Windows 和 Linux 做专门工作和验证。

进入本地实测阶段前，先把三块基础功能打磨好：

| 环节 | 现状 | 以后 |
|---|---|---|
| 取词 | 划词：AX，失败时按应用自己的 Copy 菜单项，再失败用 Cmd+C，都完整恢复剪贴板；带来源应用、窗口标题、可编辑三态和前后文 | OCR 等其他取词方式 |
| Action | 翻译、释义、优化提示词、整理输出，都由 `providers/prompt` 的声明驱动 | 插件 |
| 输出 | 墨色面板：文本、流式 Markdown、长文阅读、复制、替换原文 | 插件只描述内容，界面仍由 `app/` 渲染 |

实测时要有四个功能：划词翻译、提示词优化、通俗释义、Agent 输出优化。此外还要有两个新模块：

- **记忆：** 在本地记录每次使用，提炼出用户在不同情境下的偏好。
- **自动路由：** 在取词和 Action 之间，根据当前信号和记忆自动选择功能，用规则加 Jev 判断，猜错时可以一键改正，改正结果写回记忆。

设置分两层：产品设置（模型服务和 Key、快捷键、记忆、路由等）和功能设置（每个功能或插件声明自己的设置项，界面由宿主统一生成）。

拆解和顺序见 Linear 项目 [macOS 本地实测](https://linear.app/yeman/project/macos-本地实测-decd5658cbd1)（GLO-7 至 GLO-31）和 **Gloss 0.1.0**（GLO-26、GLO-32 至 GLO-40）。截至 2026-11-06，0.1.0 的代码都已完成，其中 GLO-37（自动更新）已取消。GLO-7、GLO-22 等负责人实测，仍为 Todo。需要负责人实测的验收项写在各 issue 和[实测清单](research/2026-11-05-local-trial.md)里。

Gloss 定位为 Bob 的替代品，两者不会同时运行，所以不处理快捷键冲突。

## 已知问题

这里记录已确认的事实。要不要修、何时修，讨论后在 Linear 规划。

| 问题 | 影响 | 状态 |
|---|---|---|
| 真实服务没有按场景验证：负责人本机经本地网关跑过四个功能和 Jev（日志里首字约 0.7–1.2 秒），但错误场景、延迟记录都没做 | Jev 的区分效果和错误场景下的表现未知 | 等负责人实测（GLO-7） |
| 在 Claude 桌面端选中多段文字时，有时提示“先选中一段文字”（负责人录屏） | 取词失败 | 未复现；已加 `AXManualAccessibility`、AX 超时，修了 Cmd 键卡住；兜底 Cmd+C 改为只发给目标进程（面板是键盘窗口时全局 Cmd+C 会进面板，可能是原因之一，未证实），待实测（GLO-9） |
| Arc 里取不到选中文字：取词发给了盖在它上面的 Cua Driver 窗口（负责人日志和只读监视实测，46/46） | 其他应用的透明窗口盖在 Chromium 内核的应用上时同样会发生 | 已修（v0.1.2），透明窗口复现后验证通过，负责人在 Arc 上确认可用（[排查](research/2026-11-06-arc-capture.md)） |
| Chrome、Chromium 里没有写回凭证（实测 `token=0`）；Arc 走 AX，替换未测 | 面板不能替换原文，也拿不到前后文 | 要改只能开 `AXEnhancedUserInterface`，第一次要等 1–3 秒，长期代价未测；未讨论 |
| Cmd+C 超过等待时间才生效时不再恢复剪贴板（读代码得出；Chrome 刚启动时测到过一次 712ms） | 用户的剪贴板可能被选中文字替换 | 菜单路径减少了它；只走 Cmd+C 的应用仍可能发生，未改 |
| Cmd+C 兜底曾让系统认为 Cmd 一直按着（实测 HID 标志），旧 helper 也有 | 下次取词多等 400ms，可能影响用户输入 | 已修，TextEdit 实测 |
| 点过面板后，面板会成为键盘窗口（Gloss 不激活），全局发出的 Cmd+V 进了面板，替换没落地（TextEdit 实测） | 面板里的替换失败 | 已修：AX 优先，按键只发给目标进程；面板替换在 TextEdit 实测成功。按进程发键在沙盒或特殊应用里是否被处理，未测 |
| AX 写入是否进入各应用的撤销栈 | 替换后可能无法 Cmd+Z | TextEdit 可撤销；其他应用未测 |
| “最近一次明确选择”曾是全局的，一次手动选择会带偏之后的路由 | 路由可能被一次选择带偏 | 已收窄到同一应用、同类文字、两小时内（GLO-40），效果看实测 |
| 只读环境里的英文单词规则一律判翻译，用户可能想看释义 | 这类情况不会交给 Jev 或记忆 | 观察中 |
| 程序 16.44 MB（字体约 4 MB，粗体加了 1.3 MB）；空闲 37–40 MB，其中 mygo 框架约 35 MB；启动和打开设置时有不到一秒的 90–130 MB 峰值，来自 Metal 和 mygo，菜单栏示例程序同样会有（macOS 实测，见[内存](research/2026-11-06-memory.md)） | 偏离“守住轻量”，大头不在 Gloss 自己 | 已查明，能压的已压 |
| 关闭设置后比空闲多约 7–10 MB（AppKit 原生分配，反复开关不增长） | 打开过设置后常驻 46–47 MB | 不用 cgo 无法归还，接受 |

| 面板交互仍有抖动、不够丝滑（macOS 160Hz，负责人实测）；录屏里点击时有 57–82ms 的帧间隔，原因未查明 | 手感未达预期 | 元素生命周期已修，加了帧间隔日志，卡顿原因仍未查明（GLO-10） |
| mygo 只在应用激活时跟踪鼠标，而 Gloss 从不激活。macOS 上面板用私有 API `SetsCursorInBackground` 自己设置鼠标样式 | 系统升级后可能失效，失效时只是样式不变 | 观察中 |
| 面板仍是蓝色强调色和纯文字页脚，设置窗口已换成墨与荧光 | 两边暂时不是一个产品 | 放到 0.1.3（GLO-48，GLO-41 和 GLO-43 剩下的部分依赖它） |
| 面板未实测：关闭动画、点外部关闭后的拖选变淡、单词大字号、音标块、甩动惯性、已打开时滑到新位置、减弱动效、1 倍屏、托盘新菜单项、面板里的修复按钮 | 可能有问题 | 待验证 |
