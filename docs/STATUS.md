## 当前重点

**只做 macOS。** Windows 开发自 2026-11-05 起暂停（负责人决定），Linux 也不考虑。代码继续保持跨平台写法，但不再为 Windows 和 Linux 做专门工作和验证。

进入本地实测阶段前，先把三块基础功能打磨好：

| 环节 | 现状 | 以后 |
|---|---|---|
| 取词 | 只有划词：AX，失败时用 Cmd+C 兜底 | OCR 等其他取词方式 |
| Action | 只有翻译（`providers/openai`） | 通过插件接口提供释义、热梗解释等功能 |
| 输出 | 墨色面板，按 BlockKind 统一渲染 | 流式 Markdown、长文阅读、替换原文；插件只描述内容，界面仍由 `app/` 渲染 |

实测时要有四个功能：划词翻译、提示词优化、通俗释义、Agent 输出优化。此外还要有两个新模块：

- **记忆：** 在本地记录每次使用，提炼出用户在不同情境下的偏好。
- **自动路由：** 在取词和 Action 之间，根据当前信号和记忆自动选择功能，用规则加 Jev 判断，猜错时可以一键改正，改正结果写回记忆。

设置分两层：产品设置（模型服务和 Key、快捷键、记忆、路由等）和功能设置（每个功能或插件声明自己的设置项，界面由宿主统一生成）。

拆解和顺序见 Linear 项目 [macOS 本地实测](https://linear.app/yeman/project/macos-本地实测-decd5658cbd1)（GLO-7 至 GLO-31），分五个阶段：地基、输出、功能、记忆与自动路由、进入实测。最先做的是 GLO-27（最小公共契约），它没有依赖。

Gloss 定位为 Bob 的替代品，两者不会同时运行，所以不处理快捷键冲突。

## 已知问题

这里记录已确认的事实。要不要修、何时修，讨论后在 Linear 规划。

| 问题 | 影响 | 状态 |
|---|---|---|
| Cmd+C 兜底只恢复纯文本剪贴板 | 可能丢失图片等内容 | 必须在发布前修复 |
| macOS 查询前台应用要启动 `lsappinfo`，约 20ms | 取词变慢 | 待改用 NSWorkspace |
| 原型曾有一次 AX 和 Cmd+C 都失败，原因未确认 | 取词可靠性 | 观察中 |
| 程序增至约 13.9MB，内存常驻 44–46MB，绘制后短暂峰值约 100MB（macOS 实测，此前 31–33MB） | 偏离“守住轻量”，峰值来源未查明 | 待讨论 |
| 面板交互仍有抖动、不够丝滑（macOS 160Hz，负责人实测）；录屏里点击时有 57–82ms 的帧间隔，原因未查明 | 手感未达预期 | 待修 |
| 在 Claude 桌面端选中多段文字时，有时提示“先选中一段文字”（负责人录屏） | 取词失败 | 待查 |
| helper 客户端同步等待响应，没有超时和重启；各种取词失败都显示“先选中一段文字”（静态核对） | helper 卡住时 Gloss 失效且看不出原因 | 待修（GLO-28） |
| Rust AX 路径中 Create/Copy 得到的引用未释放（`macos.rs` 的 `read_selection`，静态核对，泄漏量未测） | 长时间运行可能泄漏 | 待修（GLO-28） |
| `app/panel.go` 把 `ui.Element` 存进面板状态，而 mygo 规定元素在下一次构建前失效（静态核对，未复现问题） | 可能读到失效元素 | 待修（GLO-10） |
| 面板接受任意 run 的事件，取消撤回不了已排进 UI 队列的旧回调（静态核对） | 快速切换或重试时可能闪回旧结果 | 待修（GLO-19） |
| mygo 只在应用激活时跟踪鼠标，而 Gloss 从不激活。macOS 上面板用私有 API `SetsCursorInBackground` 自己设置鼠标样式 | 系统升级后可能失效，失效时只是样式不变 | 观察中 |
| 面板未实测：关闭动画、点外部关闭后的拖选变淡、单词大字号、音标块、重试按钮、甩动惯性、已打开时滑到新位置、长文滚动和隐藏的滚动条、减弱动效、1 倍屏 | 可能有问题 | 待验证 |
