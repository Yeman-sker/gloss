# 内存：空闲、设置窗口和启动峰值（GLO-39）

**日期：** 2026-11-06　**平台：** macOS 27.0.1，Apple Silicon，1 个 160Hz 屏　**构建：** `make app` 生成的 `build/darwin-arm64/Gloss.app`（0.1.0，主程序 16.44 MB）

## 怎么测

- 从 .app 里的可执行文件启动，HOME 指向隔离目录。配置里有一个服务（`api_key`、`model` 填了占位值），这样启动时不弹欢迎窗口。
- 用 `footprint -p <pid>` 读物理占用（活动监视器显示的就是它），用 `heap <pid>` 读进程的峰值。
- 第二次启动 Gloss 会让第一个实例打开设置；关设置用 System Events 点窗口的关闭按钮。没有向其他应用发送按键。
- 对照组：mygo v0.7.4 自带的 `examples/menubar-native`（只有菜单栏图标），用同样的 `-trimpath -ldflags="-s -w"` 构建。

## 结果（已实测）

| 状态 | Gloss | menubar-native（框架底数） |
|---|---|---|
| 启动后第一秒 | 约 97 MB，持续约 0.7 秒 | 约 91 MB |
| 空闲（启动 10–30 秒后） | 37–40 MB | 35 MB |
| 设置窗口打开并停稳 | 50–57 MB | — |
| 设置窗口刚打开的一两秒 | 最高 128 MB | — |
| 关闭设置后 10 秒，改动前 | 49–50 MB | — |
| 关闭设置后 10 秒，改动后 | 46–47 MB | — |
| 连续打开、关闭设置 3 次 | 每次关闭后都是 47 MB，没有增长 | — |

上一轮的数据（2026-11-05，[本地实测清单](2026-11-05-local-trial.md)）：用模拟服务跑完四个功能后是 46 MB。这一轮**没有重测面板**，因为触发面板要在别的应用里选中文字并按快捷键，而这次不向用户的窗口发送按键。

## 分析

- **启动峰值不是 Gloss 自己的。** 峰值时最大的一项是 54 MB 的 `Owned physical footprint (unmapped) (graphics)`。mygo 的菜单栏示例也有同样的峰值，所以它来自 Metal 初始化或 mygo 的渲染器，一秒内就会还掉。打开设置时的峰值也是这一类。证据：footprint 分类，再加上对照组。
- **空闲时 Gloss 只比框架底数多 2–5 MB。** 这部分是打包字体、Markdown 和配置。Go 堆只有约 4 MB（`GODEBUG=gctrace=1`：`4->4->1 MB`）。
- **关闭设置后有 7–10 MB 没回到空闲水平**，主要是 `Malloc Small` 从 14 MB 涨到 19 MB。这是原生分配，heap 统计约 14.5 MB 还在使用中，推测是 AppKit 为普通应用（进 Dock、有菜单栏）建立的状态。不用 cgo 就没法让 malloc 主动归还这部分，而且反复开关不会增长，所以不再处理。
- **能减的已经减了。** Go 会把释放的内存留一段时间再还给系统。现在面板淡出或设置窗口关闭 5 秒后，调用一次 `debug.FreeOSMemory`（`app/app.go` 的 `settle`），关闭后的占用由 49–50 MB 降到 46–47 MB。

## 没有测

- 面板运行时和长篇 Markdown 时的占用（本轮未重测，见上）。
- 真实模型服务下的占用。
- 1 倍屏和外接多屏。
- 长时间（几天）运行后的占用。负责人日常使用时可以留意活动监视器里的“内存”一栏。
