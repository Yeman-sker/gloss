## 准备

1. `make app`，把 `gloss.app` 拖进“应用程序”，首次运行时在“系统设置 › 隐私与安全性 › 辅助功能”里允许它。
2. 托盘 › 打开配置文件，填 `services.main.api_key` 和 `model`。要试 Jev 时按 [Jev 调研](2026-11-05-jev.md) 加一个服务。
3. 托盘 › 登录时启动（需要从 .app 运行）。
4. `go run ./cmd/smoke -n 3` 记录真实服务的首字和总耗时（GLO-7），结果补到本文。

## 每天结束时

```bash
go run . stats 1      # 当天的改正率、未知比例、回退率、路由耗时
go run . recent 30    # 最近 30 次，不含文本
go run . label <会话> right|wrong   # 给没改正但其实选错（或确实选对）的会话标注
```

只有标注过的会话才算“已确认”。没改正不等于选对了。

## 场景清单

负责人补充自己实际用到的应用后再开始。每个场景记下：是否取到、选了哪个功能、对不对、改正后是否满意、写回是否成功。

| 功能 | 典型场景 | 故障场景 |
|---|---|---|
| 翻译 | Safari/Chrome 里的英文段落；PDF（预览）里的句子；单个生词 | 网页里跨段落选择；含代码的英文 |
| 释义 | 中文技术文章里的术语；新闻里的梗或缩写；论文里的一句话 | 取不到上下文时是否编造背景；同一个词在不同文章里解释是否不同 |
| 优化提示词 | ChatGPT 网页、Claude 桌面端输入框里自己写的提示词，改写后替换 | 选区在等待期间被移动；替换后 Cmd+Z；不可编辑的地方不应出现“替换” |
| 整理输出 | Claude Code、Codex 在终端或桌面端的长输出 | 输出里有代码和路径，核对改写前后事实是否一致 |
| 路由 | 同一段英文在浏览器和输入框里分别触发 | 在 Claude 里选中的普通英文句子不应被当成 Agent 输出 |

## 观察重点

- 取词：Claude 桌面端多段选择（GLO-9）、终端、Electron 应用；剪贴板是否被弄丢。
- 面板：160Hz 屏上的手感（GLO-10）。用 `GLOSS_FRAMELOG=1 ./bin/gloss` 运行，日志会记下动画期间超过 25ms 的帧间隔。
- 路由：哪些情况经常改正；“最近一次选择”的回退是否太强。
- 内存：`footprint -p $(pgrep -x gloss)`，基线 46MB（2026-11-05，模拟服务跑完四个功能后）。
